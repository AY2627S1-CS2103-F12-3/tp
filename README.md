* This is **a sample project for Software Engineering (SE) students**.<br>
  Example usages:
  * as a starting point of a course project (as opposed to writing everything from scratch)
  * as a case study
* The project simulates an ongoing software project for a desktop application (called _AddressBook_) used for managing contact details.
  * It is **written in an object-oriented programming (OOP) style** and provides a **reasonably well-written** codebase of about 6 KLoC. It is **larger** than what students typically write in beginner-level software-engineering modules, without being overwhelming.
  * It comes with a **reasonable level of user and developer documentation**.
* It is named `AddressBook Level 3` (`AB3` for short) because it was initially created as a part of a series of `AddressBook` projects (`Level 1`, `Level 2`, `Level 3` ...).
* For the detailed documentation of this project, see the **[Address Book Product Website](https://se-education.org/addressbook-level3)**.
* This project is a **part of the se-education.org** initiative. If you would like to contribute code to this project, see [se-education.org](https://se-education.org/#contributing-to-se-edu) for more info.

# RecruiterBuddy Use Cases

## Must-have

- [ ] **Target role:** Recruiter  
  **Use case:** The recruiter creates a role opening with its title and required experience level to track the department’s active recruitment needs.

- [ ] **Target role:** Recruiter  
  **Use case:** The recruiter adds a candidate to a specific open role, including the candidate’s contact information, to maintain applicant details in one place.

- [ ] **Target role:** Experienced user  
  **Use case:** The experienced user accesses a comprehensive guide to all commands and their features to understand available functionality and how to use it.

- [ ] **Target role:** Recruiter  
  **Use case:** The recruiter records a candidate’s interview details, including the scheduled time and assigned interviewers, to coordinate upcoming evaluations.

- [ ] **Target role:** User  
  **Use case:** RecruiterBuddy automatically saves data after each change and loads it at startup so the user can continue working without losing saved information.

- [ ] **Target role:** Recruiter  
  **Use case:** The recruiter adds notes to a candidate’s profile to reference evaluator comments when making hiring decisions.

- [ ] **Target role:** Recruiter  
  **Use case:** The recruiter closes a job opening after it has been filled or recruitment has ended to keep the active roles list current.

- [ ] **Target role:** User  
  **Use case:** The user deletes a candidate record that was entered incorrectly or is no longer needed.

- [ ] **Target role:** Recruiter  
  **Use case:** The recruiter updates the number of openings for a role to track the remaining vacancies.

## Optional

- [ ] **Target role:** Prospective user  
  **Use case:** The prospective user views sample roles and candidate records to understand how RecruiterBuddy may look with department-specific information.

- [ ] **Target role:** First-time user  
  **Use case:** The first-time user receives a brief introduction to key commands to begin using the main features without feeling lost or overwhelmed.

- [ ] **Target role:** First-time user  
  **Use case:** The first-time user displays candidate and role status definitions with a single command to understand what each recruitment pipeline stage represents.

- [ ] **Target role:** User preparing RecruiterBuddy for live use  
  **Use case:** The user removes all sample data with a single command to clear experimental records and begin with a clean workspace.

- [ ] **Target role:** Inexperienced user  
  **Use case:** The inexperienced user receives guidance for correcting an invalid command so the user can correct it and try again.

- [ ] **Target role:** User  
  **Use case:** The user undoes the most recent *n* changes to correct mistakes.

- [ ] **Target role:** Recruiter  
  **Use case:** The recruiter updates a candidate’s status to track the candidate’s progress through the recruitment pipeline.

- [ ] **Target role:** Recruiter  
  **Use case:** The recruiter updates a candidate’s details, such as the interview date, to keep the candidate’s profile current.

- [ ] **Target role:** Recruiter adding candidates  
  **Use case:** The recruiter receives a warning if a candidate with the same email address or phone number already exists to avoid creating duplicate profiles.

- [ ] **Target role:** Recruiter  
  **Use case:** The recruiter filters candidates by status or other details to identify candidates requiring follow-up and ensure none are overlooked.

- [ ] **Target role:** User  
  **Use case:** The user searches for a candidate by name or other relevant details to locate the candidate’s record.

- [ ] **Target role:** Experienced user  
  **Use case:** The experienced user creates custom candidate statuses to tailor the recruitment pipeline to specific needs.

- [ ] **Target role:** Recruiter seeking to re-engage past applicants  
  **Use case:** The recruiter views a past applicant’s saved contact information to contact them about new opportunities.

- [ ] **Target role:** Recruiter  
  **Use case:** The recruiter filters candidates by role to focus on one recruitment pipeline at a time.

- [ ] **Target role:** Experienced user  
  **Use case:** The experienced user deletes multiple candidate records at once to remove records that are no longer needed.

- [ ] **Target role:** Experienced user  
  **Use case:** The experienced user adds multiple candidate applications at once to enter several applications efficiently.

- [ ] **Target role:** Experienced user  
  **Use case:** The experienced user updates the statuses of multiple candidates at once to move or reject candidates as a group.

- [ ] **Target role:** Expert user  
  **Use case:** The expert user creates shortcuts for common tasks to complete frequently performed actions more efficiently.

- [ ] **Target role:** Expert user  
  **Use case:** The expert user exports all role and candidate data to a local CSV file to back up the information or use it in external reporting tools.

- [ ] **Target role:** Expert user  
  **Use case:** The expert user imports role and candidate data from a local CSV file to restore backed-up information or access it on another device.

- [ ] **Target role:** Expert user  
  **Use case:** The expert user exports selected candidate records to a CSV file to share relevant information with the company database or other authorized recipients.

- [ ] **Target role:** Expert user  
  **Use case:** The expert user views an automated audit trail of a candidate’s status changes to review how long the candidate spent at each recruitment stage.
